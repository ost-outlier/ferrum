# Cross-crate register (A5)

Workspace-wide register of capabilities whose status depends on another crate (brief section 5, A5). One entry per capability. Written by the `ferrum-state` audit (crate 1 of 4); later audits add entries and update states.

Columns: **id**, **requesting crate / item** (the item whose status depends on the capability), **capability**, **cm6 evidence** (`CodeMirror6/…`), **owner** (Ferrum crate that must provide it, per the dependency graph in `ferrum-foundation.md` §4.1), **what exists** (`ferrum/…`, or "absent after searching …"), **state** (`open` / `resolved` / `wontfix`), **source** (raw evidence file in `state/raw/`).

All `ferrum-state` entries point *upward*: they are capabilities that cm6 puts in `@codemirror/state` and that `view`, `language` or `commands` use, or items placed in the wrong crate. `ferrum-state` has no Ferrum dependency, so no state item is `BLOCKED: <crate>`.
